# R11 comparison: prime through SDL on actual race entry

R10's startup priming was physically felt, but the first game pulse was still missing. The log shows about 34 seconds between them, with no tracked engine stop/reset callback before the first game pulse. The user separately waited 40 seconds during play and still received the next vibration. A simple idle-time explanation is therefore unsupported.

R11 removes startup Core Haptics playback priming. Controller open still constructs/starts the engines without creating or playing a pattern, preserving the user-confirmed stutter improvement. R11 reads the native MAME module's live-race telemetry flag at foreground SDL event-loop entry. A false-to-true transition sends a 70% / 120ms priming request via the same native SDL_GameControllerRumble path as game impacts. A held flag does not repeat the request; later race entries do. Original game rumble arguments/results and SDL's normal stop timer remain unchanged.

The C export tcvr_mame_rally_telemetry at RVA 0x51b0 is verified to copy exactly six 32-bit values into a float buffer, without side effects. Producer code encodes live race state 3, phase 5/7, substate 7 and valid remaining time in the first float. The upstream debug.tcvr.rally_anyState override can broaden that predicate; normal settings leave it off. CI verifies the getter and producer byte sequences in original and converted modules. Runtime checks the module, RVA and all getter bytes before calling it; mismatched or missing modules disable race priming. This does not read or write ROM bytes or mutate the telemetry/result queues.

Open controller pointers are tracked with SDL open reference counts. Injected rumble and close are serialized so no closed handle is used. Normal resume does not replay priming while the race flag remains true. No new PAD button or menu option is added. Tests cover getter guards, valid/invalid/held/new-race states, one native priming call per open handle and retained/closed-handle lifetime, plus existing input/audio/haptics behavior.

This is an unverified device comparison, not a confirmed fix. Race-entry priming may be felt as a start vibration; it may itself be missing if the first SDL-routed output is discarded. Device testing must establish whether the first subsequent collision vibration is delivered without stutter. Select-Coin and fixed 4x gain remain unchanged. No raw device log, ROM or protected game data is published.
